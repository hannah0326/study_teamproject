# 팀 편성 웹 앱 구현 계획

> **실행 방식:** 이 세션에서 직접 실행함. 한 단계가 끝나면 멈추고, 사용자가 화면에서 직접 확인한 뒤 다음 단계로 감. 각 작업의 체크박스(`- [ ]`)로 진행을 표시함.
> **커밋·푸시:** 사용자가 허락하기 전에는 하지 않음. 단계 끝에 커밋 여부, 메시지, 태그와 화면 캡처(`img/`) 저장 여부, 푸시 여부를 묻고 답대로만 함.

**목표:** 학생이 스스로 팀을 편성하고(지원, 투표), 마감 뒤 남은 학생을 AI와 앱이 규칙에 맞게 배정하는 Streamlit 웹 앱을 만들어 배포함.

**구조:** 규칙(`rules`)과 배정(`solver`)은 DB와 화면에 의존하지 않는 순수 함수로 만듦. 메모리 엔진(`engine`)과 DB 서비스(`service`)가 같은 판정 함수를 부르고, 같은 시나리오 데이터로 둘 다 시험함. 화면(`ui_*`)은 서비스만 부름.

**기술:** Python 3.12, Streamlit(`st.fragment`, `st.container(key=)`), Supabase Postgres(`psycopg` v3 + `psycopg_pool`), `bcrypt`, `requests`, `pytest`, Streamlit `AppTest`.

**명세:** [docs/PRD.md](PRD.md) (이하 "PRD"). 절 번호는 PRD의 것.

## 전체에 적용하는 제약
- 새로 만드는 모든 파일 첫머리에 작성 일시를 KST 주석으로 적음. 시각은 PowerShell `[System.TimeZoneInfo]::ConvertTimeBySystemTimeZoneId([DateTime]::UtcNow, 'Korea Standard Time')` 로 구함.
- 저장소에 올라가는 모든 텍스트(코드 주석, 문서, 커밋 메시지)는 한국어. 식별자, 명령어, 고유명사는 예외.
- 키, DB 주소, 관리자 비밀번호는 코드, 문서, 커밋, 화면, 채팅에 쓰지 않음. 환경 변수 → `st.secrets` 순으로 읽고, 있음/없음만 출력. 커밋 전에 `git check-ignore .env` 로 `.env` 가 무시되는지 확인.
- 모든 테이블 이름은 `tf_` 로 시작. 상태 값은 한국어(`대기`, `승인`, `거절`, `찬성`, `거부`).
- 화면 요소 key는 PRD 5.2절 표와 정확히 같게. 새로 고침 단추는 만들지 않음.
- 모델 이름은 `teamapp/config.py` 한 곳에만 둠. `openrouter/free` 는 쓰지 않음.
- 특정 학생 이름이나 순서에 맞춘 코드 금지. 역할은 CSV 열에서만 읽음. 연습용 명단은 `tests/fixtures/` 에만 둠.
- 실제 사람의 이름과 학번 금지. 연습용 가상 명단만 사용.
- 문서를 쓰거나 커밋하기 전에, 사용자가 정한 금칙어 5개가 저장소 파일에 섞였는지 검색(명령에만 쓰고 문서와 시험 파일에는 그 낱말을 적지 않음).
- 무료 AI 호출은 하루 50회, 분당 20회. 자동 테스트는 가짜 응답만 쓰고, 개발 중 실제 호출은 4단계의 계획된 횟수만 함.

## 검토 초점 (명세가 말하지 않지만 사용자가 마주칠 입력)
각 줄은 맡은 작업의 시험으로 고정함.
1. 로그인 입력의 앞뒤 공백(`" 2026301 "`)은 무시하고 로그인됨 → 작업 2.2.
2. 이미 결정된(거절, 승인) 지원에 늦게 온 찬성/거부는 상태를 바꾸지 않고 지금 상태만 `result` 로 보여 줌 → 작업 1.3, 3.1.
3. 팀 수가 학생 수보다 많거나(예: 학생 8명, 팀 10개) 팀 수가 1이어도 명단 올리기가 되고, 배정이 안 되면 이유를 보여 줌 → 작업 1.5, 2.3.
4. AI 응답이 코드 블록(```` ```json ````)에 싸여 있거나, 없는 학번·없는 팀 번호를 쓰거나, 이미 팀에 있는 학생을 옮기면 실패로 처리하고 다음 모델로 넘어감 → 작업 4.2, 4.3.
5. 학생 세션으로는 서버 쪽에서 관리자 기능(명단 올리기, 마감, 배정, 확정)을 부를 수 없음 → 작업 2.2, 4.1.
